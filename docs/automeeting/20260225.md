## 1️⃣ UX/UI 개선점

### 1-1. 경로 히스토리 시각화
**문제점**: 최근 검색은 있지만 과거 경로를 다시 보기 어려움  
**제안**: 
- 검색 이력을 시간대별로 그룹화 (오늘, 어제, 이번주, 이전)
- 각 검색마다 미니 지도 썸네일 표시
- 자주 검색하는 경로 패턴 자동 추천 ("출퇴근 루트" 등)

### 1-2. 터치 제스처 개선 ⭐
**문제점**: 모바일에서 지도 핀칭/패닝이 검색 오버레이와 충돌 가능  
**제안**:
- 스와이프로 결과 리스트 토글
- 길게 눌러서 지도에 직접 핀 추가
- 두 손가락 드래그로 경로 조정

### 1-3. 실시간 교통 정보 표시
**문제점**: 정적인 경로만 표시, 현재 교통상황 반영 안 됨  
**제안**:
- Naver 교통정보 API 연동
- 경로에 색상 코딩 (초록=원활, 노랑=지체, 빨강=정체)
- "지금 출발하면 X분" 실시간 표시

### 1-4. 경유지 선택 플로우 개선 ⭐⭐
**문제점**: 경유지를 선택하면 바로 경로가 업데이트되는데, 여러 옵션을 비교하기 어려움  
**제안**:
- "비교 모드" UI 개선
- 경유지 카드에서 "이 경로로 네비 시작" 버튼 추가
- 경유지별 예상 소요시간 더 명확하게 표시

### 1-5. 다크모드 자동 전환 ⭐
**문제점**: 이미 다크모드는 있지만, 시간대별 자동 전환 없음  
**제안**:
- 일몰/일출 시간 기준 자동 전환 옵션
- "운전 모드" (높은 대비, 큰 글씨)

## 2️⃣ 신규 기능 제안

### 2-1. 다중 경유지 지원 ⭐⭐⭐
**문제점**: 현재 1개 경유지만 추천. 실제로는 "은행 → 우체국 → 약국" 같은 다중 경유지 필요  
**제안**:
- A → C1 → C2 → B 경로 최적화
- 경유지 순서 자동 재배치 (TSP 알고리즘)
- "이 근처에서 추가로 볼 곳" 제안

### 2-2. 음성 검색
**문제점**: 운전 중 텍스트 입력 위험  
**제안**:
- Web Speech API로 음성 인식
- "아이유 콘서트장 가는 길에 스타벅스" 같은 자연어 처리
- 네비 음성 안내 통합

### 2-3. 친구와 중간지점 찾기 ⭐⭐⭐
**문제점**: 현재는 A→B 경로 위주. 실제로는 "서로 만나기 편한 곳"도 중요  
**제안**:
- 다수 출발지 입력 (친구1, 친구2, 나)
- Voronoi 다이어그램으로 중간지점 계산
- 각자 소요시간 최소화

### 2-4. 경유지 예약/대기시간 정보
**문제점**: 경유지에 도착했는데 대기 1시간이면 의미 없음  
**제안**:
- 네이버 플레이스 크롤링으로 "혼잡도" 표시
- "지금 방문하면 대기 약 10분" 예측
- 예약 가능한 곳은 바로 예약 링크

### 2-5. 경로 공유 및 협업 ⭐⭐
**문제점**: 혼자만 볼 수 있음. 가족/동료와 경로 공유 어려움  
**제안**:
- 카카오톡/텔레그램으로 경로 공유 (이미 있음, 개선 필요)
- QR 코드로 지도 바로 열기
- "함께 가기" 모드 (실시간 위치 공유)

## 3️⃣ 경쟁력 분석

### 경쟁 서비스
- **네이버 지도**: 경유지 추가 수동, Detour Cost 개념 없음
- **카카오맵**: 멀티 경유지 지원하지만 최적화 약함
- **Google Maps**: 해외 서비스라 국내 상세 정보 부족

### MidWayDer의 강점
1. ✅ **Detour Cost 알고리즘**: 실제 이탈 거리/시간 계산
2. ✅ **PostGIS 공간 쿼리**: 대용량 데이터에서도 빠른 검색 (< 3초)
3. ✅ **PWA 지원**: 앱 설치 없이 바로 사용

### 약점
1. ❌ **데이터 범위**: 일부 카테고리만 지원 (다이소, 스타벅스 등)
2. ❌ **실시간성**: 교통 정보, 영업시간, 재고 정보 없음
3. ❌ **커뮤니티**: 사용자 리뷰/평점 시스템 부재
