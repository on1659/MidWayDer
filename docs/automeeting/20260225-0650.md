## 🎯 UX/UI 개선점 (새로운 시각)

### 1. **성능 지표 시각화 부족**
**현재 문제:**
- 백엔드에서 검색 시간(duration), API 호출 수(apiCallsUsed) 추적 중
- 하지만 사용자에게 보여주지 않음
- "빠르다"는 걸 체감할 수 없음

**개선안:**
- 검색 완료 시 배지 표시: "0.8초만에 50곳 분석완료 ⚡"
- 하단에 작은 텍스트: "API 호출 41회 사용 (최적화율 98%)"
- 검색 시간이 3초 이상이면 경고 표시

**사용자 가치:** 신뢰도 향상, 기술적 우위 강조

---

### 2. **주소 복사 기능 없음**
**현재 문제:**
- 경유지 주소를 복사하려면 길게 선택해야 함 (모바일에서 불편)
- 주소를 메모장이나 메신저로 공유할 때 번거로움

**개선안:**
- 각 결과 카드에 "📋 복사" 버튼 추가
- 클릭 시 주소 클립보드 복사 + 토스트 알림
- PlaceDetail 바텀시트에도 추가

**사용자 가치:** 모바일 편의성 대폭 향상

---

### 3. **네비게이션 앱 연동 없음**
**현재 문제:**
- 경유지를 찾았지만, 실제 네비 앱으로 전환하려면 수동 입력 필요
- "찾았으니 이제 어떻게 가지?"에 대한 답이 없음

**개선안:**
- PlaceDetail 하단에 "네비 연결" 버튼 그룹
  - 카카오내비 (kakaonavi://...)
  - 네이버지도 (nmap://...)
  - 티맵 (tmap://...)
- 각 앱 딥링크로 경유지 주소 전달
- 앱 미설치 시 앱스토어/플레이스토어 링크

**사용자 가치:** 검색→네비 전환 원클릭, 사용자 여정 완결

---

### 4. **에러 복구 기능 없음**
**현재 문제:**
- 검색 실패 시 에러 메시지만 표시
- 다시 시도하려면 뒤로가기 → 검색 버튼 재클릭
- 네트워크 일시 오류 시 사용자 이탈

**개선안:**
- 에러 상태에 "다시 시도" 버튼 추가
- 자동 재시도 (최대 2회, 1초 간격)
- 에러 메시지 개선:
  - "네트워크 연결을 확인해주세요" (fetch error)
  - "네이버 API 한도 초과. 잠시 후 다시 시도해주세요" (429)
  - "경로를 찾을 수 없어요. 주소를 확인해주세요" (404)

**사용자 가치:** 에러 회복력 향상, 사용자 이탈 방지

---

### 5. **키보드 네비게이션 미지원 (데스크톱)**
**현재 문제:**
- 데스크톱에서 모든 조작이 마우스 클릭 필수
- 파워유저나 접근성 사용자에게 불편
- 검색창 포커스 단축키 없음

**개선안:**
- **Cmd/Ctrl + K**: 검색 오버레이 열기
- **ESC**: 오버레이/바텀시트 닫기
- **↑/↓**: 결과 리스트 탐색
- **Enter**: 선택된 결과 확대
- **Tab**: 입력 필드 간 이동

**사용자 가치:** 데스크톱 사용성 향상, 접근성 준수

---

### 6. **빈 검색 결과 안내 부족**
**현재 문제:**
- 검색 결과 0개일 때: "출발지와 도착지를 설정하고 검색해보세요"
- 실제로는 설정했는데 결과가 없는 경우 혼란
- 왜 없는지, 어떻게 해야 하는지 안내 없음

**개선안:**
- 조건별 메시지 분기:
  - 검색 전: 기존 메시지
  - 검색 완료 + 결과 0개: "경로 주변에 [카테고리]가 없어요 😢"
  - 대안 제시: "다른 카테고리를 시도해보세요" (버튼 3개)
  - 또는: "검색 범위 확대" (1km → 3km 재검색)

**사용자 가치:** 좌절감 감소, 대안 제시로 이탈 방지

---

### 7. **시간대별 스마트 카테고리 제안**
**현재 문제:**
- 카테고리 선택이 수동
- 상황에 맞는 카테고리를 사용자가 직접 생각해야 함

**개선안:**
- 시간대별 카테고리 자동 하이라이트
  - 아침 (06-09시): ☕ 카페 (스타벅스, 이디야)
  - 점심 (11-14시): 🍚 식당, 편의점
  - 저녁 (17-20시): 🏪 편의점, 마트
  - 심야 (21-01시): 🏪 편의점 (24시)
- 검색 오버레이 상단에 작은 뱃지: "지금은 카페 시간 ☕"

**사용자 가치:** 선택 피로 감소, 개인화된 경험

---

### 8. **데스크톱 hover 프리뷰 없음**
**현재 문제:**
- 데스크톱에서도 결과를 클릭해야 경로 확인
- 여러 후보를 빠르게 비교하려면 반복 클릭 필요

**개선안:**
- 데스크톱에서 결과 카드에 마우스 오버 시:
  - 지도에 경로 프리뷰 표시 (반투명)
  - 500ms 딜레이 후 표시 (실수 방지)
  - 마우스 떠나면 프리뷰 제거
- 클릭하면 영구 선택 (기존 동작)

**사용자 가치:** 데스크톱 탐색 속도 향상

---

### 9. **즐겨찾기 알림 기능 없음**
**현재 문제:**
- 즐겨찾기 추가했지만 사용 시점에 알림 없음
- "회사 가는 길에 다이소 들르기"를 저장했는데 까먹음

**개선안:**
- 즐겨찾기에 조건 추가:
  - "월요일 아침마다" (요일 반복)
  - "출발지가 [집] 근처일 때" (위치 기반)
- PWA 푸시 알림: "다이소 들를 시간이에요!"
- 알림 시간 설정 (출발 30분 전, 1시간 전)

**사용자 가치:** 루틴 자동화, 재방문 유도

---

### 10. **경로 저장 및 공유 이미지**
**현재 문제:**
- 공유 기능은 URL만 전송
- 카카오톡 등에서 URL 미리보기 없음
- "이 경로 어때?" 하고 이미지로 보여주기 어려움

**개선안:**
- 공유 버튼 클릭 시 옵션:
  - URL 공유 (기존)
  - 이미지로 저장 (신규)
- Canvas API로 지도 캡처:
  - 경로 + 경유지 마커 포함
  - 상단에 정보 텍스트 ("출발: XX, 경유: YY, 도착: ZZ")
  - PNG 다운로드 or 클립보드 복사
- Open Graph 메타 태그 동적 생성 (서버 사이드)

**사용자 가치:** 소셜 공유 활성화, 바이럴 가능성

export function getKakaoNaviLink(lat: number, lng: number, name: string): string {
  return `kakaonavi://navigate?ep=${lat},${lng}&epname=${encodeURIComponent(name)}`;

export function getNaverMapLink(lat: number, lng: number, name: string): string {
  return `nmap://place?lat=${lat}&lng=${lng}&name=${encodeURIComponent(name)}&appname=com.midwayder`;

## 💡 추가 인사이트

### 사용자 여정 완결성
현재 MidWayDer는 "찾기"에만 집중되어 있음:
- ✅ 출발지/도착지 입력
- ✅ 경유지 추천
- ❌ **실제 네비 시작** ← 여기가 끊김!

**네비 앱 연동을 추가하면:**
- "검색 → 선택 → 네비" 전체 플로우 완성
- 사용자가 MidWayDer를 "단순 검색 도구"가 아닌 "실제 사용 도구"로 인식
- 재방문율 상승 기대

---

### 모바일 UX의 핵심: 마찰 제거
스마트폰에서 텍스트 선택/복사는 의외로 어려움:
- 손가락으로 정확한 영역 선택 어려움
- 길 주소는 여러 줄이라 더 번거로움
- "주소 복사" 버튼 하나로 해결 → UX 대폭 개선

**유사 사례:**
- 배달앱: "주소 복사" 버튼
- 메신저: 메시지 길게 눌러 복사
- 지도앱: 주소 탭 한 번에 복사

MidWayDer도 이런 편의 기능 필수!

---

### 경쟁 서비스 대비 차별화
**카카오맵/네이버지도:**
- 경유지 검색 없음 (수동 추가만 가능)
- ❌ Detour Cost 개념 없음
- ✅ 하지만 네비 앱 연동은 당연히 있음

**Google Maps:**
- "Add stop" 기능 있지만 자동 추천 없음
- ✅ 네비 통합
- ❌ 한국 지도 정확도 낮음

**MidWayDer의 차별화:**
- ✅ Detour Cost 기반 자동 추천 (유일)
- ✅ 실제 도로 거리/시간 반영
- ⏳ 네비 앱 연동 (구현 예정)

→ 네비 연동을 추가하면 "기능은 앞서고, 편의성은 동등한" 완성형 서비스!
