## 1단계: 사용자 여정 기반 UX/UI 리뷰

### A. 사용자 여정 분석 🗺️

#### 시나리오 1: 결과 10개를 한눈에 비교하려는 사용자
```
1. 검색 완료 → 10개 결과 카드 표시
2. 카드 1개당 높이 ≈ 180~220px → 10개 = 1,800~2,200px
3. 스크롤 피로 → 4~5번째 카드부터 읽지 않음 ❌
4. 결국 1등만 선택 → "더 나은 선택지"를 놓침
```

**문제점:**
- 카드에 뱃지 7~9개 + 한 줄 요약 + 주소 + 네비 버튼 → 정보 과부하
- 핵심 판단에 필요한 건 "이름 + 위치 + 이탈시간" 3가지뿐
- 빠르게 훑어보고 싶은 사용자를 위한 "간략 보기"가 없음

**개선 방향 (이번 구현):**
- "≡ 간략" 토글 → 카드를 1줄로 압축 (이름 + 📍위치 + +N분 + 네비 버튼)
- 카드 높이 180px → 44px으로 감소 → 10개를 화면 2개 내로 표시 가능

---

#### 시나리오 2: "+3분, +7분, +5분, +4분..." 숫자만 보는 사용자
```
1. 결과 카드 4개: +3분, +7분, +5분, +4분
2. "3분이 제일 좋긴 한데... 7분이랑 얼마나 차이나지?"
3. 숫자만 봐서는 직관적 비교가 어려움 ❌
4. 결국 1등 선택 (정보 활용 못함)
```

**문제점:**
- 이탈 시간을 숫자로만 표시 → 상대적 차이를 직관적으로 알 수 없음
- "이탈 비용 최적화"가 MidWayDer의 핵심인데, 시각화가 없음
- 경쟁 서비스(카카오/네이버)도 이 시각화는 없음 → 차별화 기회

**개선 방향 (이번 구현):**
- 각 카드에 상대적 이탈 비교 Progress Bar 추가
- 최단 이탈(1등)~최장 이탈(꼴등) 기준으로 바 길이 조정
- 초록(최소) → 주황(보통) → 오렌지(높음) 3단계 컬러

---

#### 시나리오 3: 새 경로 검색 후 이전 필터가 유지되는 사용자
```
1. "서울역→강남역, 다이소" 검색 → "+5분 이내" 필터 적용
2. 도착지를 "홍대입구역"으로 변경해서 재검색
3. 이전 "+5분 이내" 필터가 그대로 → 새 결과가 전부 숨겨짐 ❌
4. "결과가 왜 없지?" → 필터 초기화 버튼 못 찾고 당황
```

**문제점:**
- 필터 state가 results 변경 시 자동 초기화되지 않음
- 사용자는 "새 검색 = 초기화"를 기대함

**개선 방향 (이번 구현, bonus):**
- `useEffect(() => { reset filters }, [results])` 한 줄 추가

## 4단계: 실제 구현 (이번 세션)

### ✅ 구현 1: 이탈 비교 Progress Bar (ResultList.tsx)

**변경 내용:**
- 전체 결과(`results`) 기준으로 `maxDetourDuration`, `minDetourDuration`, `detourRange` 계산
- 각 카드 뱃지 영역 아래에 relative bar 추가 (`detourRange > 30`초일 때만 표시)
- 바 색상 3단계: 초록(< 30%) / 노랑(30~65%) / 오렌지(> 65%)
- 레이블: "최소" / "보통" / "높음"

**구현 핵심:**
```typescript
// 전체 결과 기준 min/max 계산 (컴포넌트 레벨)
const maxDetourDuration = results.length > 1
  ? Math.max(...results.map((r) => r.detourCost.duration))
  : 0;
const minDetourDuration = results.length > 1
  ? Math.min(...results.map((r) => r.detourCost.duration))
  : 0;
const detourRange = maxDetourDuration - minDetourDuration;

// 카드 내 바 렌더링
{detourRange > 30 && (
  <div className="mt-2.5 flex items-center gap-2">
    <span>이탈</span>
    <div style={{ background: 'var(--border-soft)', height: '6px' }}>
      <div style={{
        width: `${Math.max(4, ...)}%`,
        background: relative < 0.3 ? '#22c55e' : relative < 0.65 ? '#f59e0b' : '#f97316'
      }} />
    </div>
    <span>최소/보통/높음</span>
  </div>
)}
```

**UX 효과:**
- 이탈 비용 비교가 숫자 → 시각적 바로 전환
- 1등 카드: 짧고 초록 → "이게 최적!"이 한눈에 보임
- 꼴등 카드: 길고 오렌지 → "이건 이탈이 많네" 즉각 파악
- 결과 수가 1개거나 이탈 차이가 30초 이하면 바를 숨김 (무의미한 경우 제외)

### ✅ 구현 2: 컴팩트 카드 모드 (ResultList.tsx)

**변경 내용:**
- `isCompact: boolean` state 추가
- 필터 칩 영역 우측에 "≡ 간략" / "☰ 자세히" 토글 버튼 추가
- 카드 렌더링을 `isCompact ? <CompactRow> : <FullCard>` 조건부 처리

**컴팩트 모드 카드 구조:**
```
[순위] [아이콘] [이름  ··] [📍위치] [+N분] [네비▶]
```
카드 높이: 기존 ~190px → 컴팩트 ~44px (약 77% 감소)

**구현 핵심:**
```typescript
const [isCompact, setIsCompact] = useState(false);

// 토글 버튼
<button onClick={() => setIsCompact(v => !v)}>
  {isCompact ? '☰ 자세히' : '≡ 간략'}
</button>

// 카드 조건부 렌더링
{isCompact ? (
  <div className="flex items-center gap-2.5">
    {/* 순위 + 아이콘 + 이름 + 위치뱃지 + 이탈시간 + 네비버튼 */}
  </div>
) : (
  <div className="flex items-start gap-3">
    {/* 기존 전체 카드 내용 */}
  </div>
)}
```

**UX 효과:**
- "≡ 간략" 전환 시: 10개 카드를 화면 2개 내로 표시 (스크롤 85% 감소)
- 전체 비교 후 마음에 드는 카드를 "☰ 자세히"로 전환해서 상세 확인
- 컴팩트 모드에서도 핵심 3가지(이름 + 위치 + 이탈시간)와 네비 버튼 유지

## 🎯 이번 리뷰 핵심 인사이트

> **"데이터를 보여주는 것만큼, '비교하기 쉽게' 보여주는 것도 중요하다"**

- 이탈 시간 숫자는 있었는데 → 비교가 어려웠다 → **Progress Bar로 시각화** ✅

> "간략" 토글과 "비교 바"는 같은 데이터를 다르게 보는 두 가지 방식이다.
