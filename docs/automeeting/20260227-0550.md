## 1단계: 사용자 여정 기반 UX/UI 리뷰

### A. 사용자 여정 분석 🗺️

#### 시나리오 1: 결과를 보고 네비를 켜는 순간
```
1. 검색 결과 10개 → 1등 카드 탭
2. "네비 시작" 버튼 탭 → 바텀시트 열림
3. 카카오내비 / 네이버지도 / 티맵 중 선택 (매번!)
4. 어제도, 그제도, 오늘도 "카카오내비" 선택 → 💢 반복 friction
```

**문제점:**
- 같은 앱을 반복 선택하는 불필요한 마찰 발생
- 선호 앱이 없으면 무조건 3-step (탭 → 시트 → 선택)

**개선 방향:**
- 선택한 앱 `localStorage`에 저장 → 다음엔 바로 실행
- "변경" 버튼으로 언제든 다른 앱 선택 가능

---

#### 시나리오 2: 결과를 보고 선택 기준을 찾는 사용자
```
1. 검색 결과 10개 → 여러 카드 비교
2. "다들 어디로 가지?" → 아무 근거 없음 ❌
3. 1등 카드 선택 → "맞는 선택인지 모르겠음"
```

**문제점:**
- ClickLog 데이터가 쌓이고 있는데 사용자에게 전혀 노출 안 됨
- "사회적 증거(Social Proof)"가 없어서 결정 확신 부족

**개선 방향:**
- "최근 1시간 N명 관심" 뱃지로 다른 사용자의 선택 가시화
- 2명 이상부터만 표시 (최소 임계값으로 의미 있는 정보만)

---

#### 시나리오 3: 카테고리가 고정되어 "세탁소"를 찾는 사용자
```
1. 화면 열기 → 카테고리 칩 8개 (주유소, 카페, 편의점...)
2. "세탁소"가 없음 → 어떻게 검색하지? ❌
3. 결국 앱 종료 → 이탈
```

**문제점:**
- `CategorySelect` 8개 고정 카테고리 → 롱테일 수요 커버 불가
- 사용자가 직접 카테고리 텍스트 입력하는 방법이 없음

**개선 방향:** (이번 세션 구현 대상 아님, 다음 세션으로)
- 카테고리 검색 직접 입력 지원 → `CategorySelect`에 "직접 입력..." 칩 추가

---

#### 시나리오 4: 결과 카드가 너무 길어서 스크롤이 많은 문제
```
1. 검색 결과 10개
2. 카드 1개 = 이름 + 주소 + 뱃지 4~6개 + 한 줄 요약 + 네비 버튼 → 키가 큼
3. 10개 보려면 길게 스크롤 → 피로감 ❌
```

**문제점:**
- 뱃지: 이탈거리 + 이탈시간 + 루트레이블 + 인기도 + 영업상태 + 추천뱃지 + 한줄요약
- 카드당 높이가 너무 커서 3개 보면 스크롤 시작

**개선 방향:** (향후 개선)
- 접기/펼치기 패턴 도입 또는 핵심 정보만 1줄 요약 모드

## 4단계: 실제 구현 (이번 세션 상위 2개)

### ✅ 구현 1: 실시간 인기도 표시 (ClickLog 기반)

**새로 추가된 기능:**
- `GET /api/popularity?placeIds=id1,id2,...` — 최근 1시간 내 장소별 클릭 수 반환
- 최대 20개 placeId 배치 처리 (ResultList가 한 번에 요청)
- ResultList: 검색 결과 로드 후 `useEffect`로 인기도 데이터 비동기 요청
- 2명 이상부터 "🔥 N명 관심" 뱃지 표시 (노이즈 방지)
- API 실패 시 빈 데이터 반환 (UX 차단 없음)

**새 파일:**
- `src/app/api/popularity/route.ts` — 인기도 API 엔드포인트

**수정 파일:**
- `src/components/search/ResultList.tsx` — `popularityMap` 상태 + `useEffect` + 뱃지

**구현 핵심:**
```typescript
// /api/popularity — ClickLog 집계
const rows = await prisma.clickLog.groupBy({
  by: ['placeId'],
  where: {
    placeId: { in: placeIds },
    clickedAt: { gte: oneHourAgo },
  },
  _count: { id: true },
});

// ResultList — 비동기 인기도 로드
useEffect(() => {
  if (results.length === 0) return;
  const placeIds = results.map((r) => r.place.id).join(',');
  fetch(`/api/popularity?placeIds=${encodeURIComponent(placeIds)}`)
    .then((res) => res.json())
    .then((json) => { if (json.success) setPopularityMap(json.data || {}); })
    .catch(() => {});
}, [results]);

// 뱃지 표시 (2명 이상)
{recentClicks >= 2 && (
  <span style={{ background: 'var(--orange-100)', color: 'var(--orange-600)' }}>
    🔥 {recentClicks}명 관심
  </span>
)}
```

### ✅ 구현 2: 마지막 선택 네비 앱 기억

**새로 추가된 기능:**
- `getPreferredNavApp()`: localStorage에서 선호 앱 읽기

- 바텀시트 설명 문구 추가: "선택한 앱을 기억해 다음엔 바로 실행해요"

**수정 파일:**
- `src/lib/navigation-links.ts` — `getPreferredNavApp`, `setPreferredNavApp`, `NavApp` 타입 추가
- `src/components/search/ResultList.tsx` — 선호 앱 상태 + 네비 버튼 분기 + 시트 개선

**구현 핵심:**
```typescript
// navigation-links.ts
const PREFERRED_NAV_APP_KEY = 'midwayder_preferred_nav_app';

export function getPreferredNavApp(): NavApp | null {
  if (typeof window === 'undefined') return null;
  const stored = localStorage.getItem(PREFERRED_NAV_APP_KEY);
  if (stored === 'kakao' || stored === 'naver' || stored === 'tmap') return stored;
  return null;
}

export function setPreferredNavApp(app: NavApp): void {
  if (typeof window === 'undefined') return;
  localStorage.setItem(PREFERRED_NAV_APP_KEY, app);
}

// ResultList.tsx — 네비 버튼 분기
{preferredNavApp ? (
  <div className="flex items-center gap-2">
    <button onClick={(e) => handleOpenNavi(e, result.place)}>
      {preferredNavApp === 'kakao' ? '카카오내비' : ...}로 시작
    </button>
    <button onClick={(e) => handleOpenNaviSheet(e, result.place)}>변경</button>
  </div>
) : (
  <button onClick={(e) => handleOpenNavi(e, result.place)}>네비 시작</button>
)}
```
