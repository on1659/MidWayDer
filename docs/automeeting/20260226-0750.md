## A. UX/UI 개선점

### 현재 문제점 분석

#### 1. **검색 중 취소 불가** ⏳
**문제:**
- 검색 API 호출 중 (평균 2.4초) 취소할 방법이 없음
- 잘못 입력했거나 다른 검색하고 싶어도 기다려야 함
- 느린 네트워크에서는 10초+ 걸릴 수도 있음

**사용자 시나리오:**
```
사용자: 서울시청 → 강남역, 다이소 검색 클릭
[2초 경과]
사용자: 아차, 스타벅스로 바꾸고 싶은데... (기다림)
[응답 완료 후 다시 검색]
```

**영향:**
- 사용자가 실수로 검색한 경우 불필요한 대기
- API 비용 낭비 (취소 의사 있는데 완료까지 호출)
- 답답함, 통제력 상실 느낌

---

#### 2. **키보드 접근성 부재** ⌨️
**문제:**
- 경유지 리스트를 마우스/터치로만 탐색 가능
- 키보드만 사용하는 사용자(장애인, 파워유저) 불편
- WAI-ARIA 가이드라인 미준수

**현재 상황:**
- `ResultList`에 키보드 이벤트 핸들러 없음
- 포커스 스타일 없음 (탭으로 이동해도 하이라이트 없음)
- 화살표(↑↓)로 리스트 탐색 불가
- Enter/Space로 선택 불가

**영향:**
- 장애인 접근성 ❌ (WCAG 2.1 Level A 미충족)
- 파워유저 불편 (마우스 없이 빠른 탐색 불가)
- SEO/검색엔진 평가 감점

---

#### 3. **에러 복구 경험 부족** 🔄
**문제:**
- 네트워크 에러 시 "재시도" 버튼만 있음
- 재시도해도 같은 에러 반복 가능성 높음
- 자동 재시도 없음 (사용자가 직접 클릭해야 함)

**개선 여지:**
- 자동 재시도 (exponential backoff)
- 오프라인 감지 → "네트워크 연결을 확인해주세요" 명확한 메시지
- 캐시된 결과 있으면 "이전 결과 보기" 옵션 제공

### 3. 자동 재시도 + 오프라인 감지
**설명:** 네트워크 에러 시 자동 재시도 (최대 3회, exponential backoff)

**구현:**
```typescript
// lib/api-retry.ts
export async function fetchWithRetry(
  url: string,
  options: RequestInit,
  maxRetries = 3
): Promise<Response> {
  let lastError: Error;
  
  for (let i = 0; i <= maxRetries; i++) {
    try {
      const response = await fetch(url, options);
      if (response.ok) return response;
      
      // 4xx 에러는 재시도 안 함
      if (response.status >= 400 && response.status < 500) {
        throw new Error(`Client error: ${response.status}`);
      }
      
      lastError = new Error(`Server error: ${response.status}`);
    } catch (err) {
      lastError = err;
      
      if (i < maxRetries) {
        // exponential backoff: 500ms, 1s, 2s
        await new Promise(resolve => setTimeout(resolve, 500 * Math.pow(2, i)));
      }
    }
  }
  
  throw lastError!;
}

// 오프라인 감지
if (!navigator.onLine) {
  showToast('네트워크 연결을 확인해주세요 📡', 'error');
  return;
}

window.addEventListener('offline', () => {
  showToast('네트워크 연결이 끊겼어요 📡', 'warning');
});
```

**기대 효과:**
- 일시적 네트워크 문제 자동 복구
- 사용자 액션 없이 성공 가능성 높임
- 명확한 에러 메시지 (오프라인 vs 서버 에러)

### 2. 검색 취소 기능

#### 파일: `src/store/search-store.ts` + `src/components/search/SearchStatus.tsx`

**추가 기능:**
- AbortController로 API 호출 중단
- 로딩 중 "취소" 버튼 표시
- 취소 시 토스트 알림

**Zustand Store 수정:**
```typescript
// src/store/search-store.ts
interface SearchState {
  // ...
  abortController: AbortController | null;
  setAbortController: (controller: AbortController | null) => void;
}

export const useSearchStore = create<SearchState>((set, get) => ({
  // ...
  abortController: null,
  setAbortController: (controller) => set({ abortController: controller }),
  
  search: async (start, end, category, options) => {
    const controller = new AbortController();
    set({ isLoading: true, error: null, abortController: controller });
    
    try {
      const response = await fetch('/api/search', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ start, end, category, options }),
        signal: controller.signal, // ✅ 추가
      });
      
      // ...
    } catch (err) {
      if (err.name === 'AbortError') {
        set({ isLoading: false, error: '검색이 취소되었습니다' });
      } else {
        set({ isLoading: false, error: err.message });
      }
    } finally {
      set({ abortController: null });
    }
  },
  
  cancelSearch: () => {
    const { abortController } = get();
    if (abortController) {
      abortController.abort();
      set({ abortController: null, isLoading: false });
    }
  },
}));
```
