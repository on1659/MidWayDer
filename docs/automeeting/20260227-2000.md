### A. 사용자 여정 분석 🗺️

#### 시나리오 1: 시간에 쫓기는 직장인 (ETA 부재)
```
1. 서울역 → 강남역, 다이소 검색
2. 결과: 다이소 역삼점 +7분
3. "7분이면 괜찮은 것 같은데… 그러면 몇 시에 도착하지?"
4. 현재: 추가 소요 시간(+N분)만 표시 — 실제 도착 시각을 직접 계산해야 함
5. → "계산하기 귀찮아, 그냥 아는 곳 가자" 결정 이탈
```

**문제점:**
- +N분 이탈 비용 정보는 있지만 "몇 시에 도착하나요?"라는 핵심 질문에 답을 못 줌
- 사용자가 현재 시각 + 경로 시간을 머릿속에서 계산해야 함 → 인지 부하
- 특히 약속 시간이 정해진 상황에서 결정 포인트를 놓침

**개선 방향 (이번 구현):**
- 각 결과 카드 하단에 "🕐 지금 출발 시 → 경유지 N:MM / 목적지 N:MM 도착 예상" 추가
- `result.routes.toWaypoint.duration` + `result.routes.fromWaypoint.duration` 활용
- 순수 프론트엔드 계산 (API 추가 호출 없음)

```
1. 청량리역 → 잠실역, 올리브영 검색
```

**문제점:**
- 결과 없음 화면에서 제공하는 선택지: ① 다른 카테고리 선택 ② 다시 검색 — 둘 다 방향 전환 강요
- "같은 카테고리, 더 넓은 반경으로 재시도"라는 가장 자연스러운 선택지 없음
- `bufferDistance`는 이미 API가 지원하지만 UI에서 노출하지 않음

**개선 방향 (이번 구현):**
- 결과 없음 화면에 "🔍 반경 2km로 확장해서 재검색" 버튼 추가
- `search-store.ts`에 `extraOptions.bufferDistance` 파라미터 지원 추가
- 버튼 클릭 시 `bufferDistance: 2000` (기본 1000m → 2배 확장)으로 재검색

## 4단계: 실제 구현 (이번 세션)

### ✅ 구현 1: 예상 도착 시간 (ETA) 표시

**변경 파일:** `src/components/search/ResultList.tsx`

**추가 내용:**
```typescript
function getETAText(result: DetourResult): { waypoint: string; destination: string } | null {
  const toSec = result.routes?.toWaypoint?.duration;
  const fromSec = result.routes?.fromWaypoint?.duration;
  if (!toSec || !fromSec) return null;
  const now = Date.now();
  const fmt = (ms: number) => {
    const d = new Date(ms);
    return `${d.getHours()}:${String(d.getMinutes()).padStart(2, '0')}`;
  };
  return {
    waypoint: fmt(now + toSec * 1000),
    destination: fmt(now + toSec * 1000 + fromSec * 1000),
  };
}
```

**렌더 위치:** 스마트 한 줄 추천 문구 아래, Navigation 버튼 위

**UX 효과:**
- "경유지 11:43 / 목적지 11:51 도착 예상" — 결정 확신 즉시 제공
- 인지 부하 제거: 머릿속 계산 → 카드에서 바로 확인
- 빠른 비교: 여러 카드를 스캔하면서 시간대별 최적 선택 가능

## 🎯 이번 리뷰 핵심 인사이트

> **"불확실성이 아니라 확신을 팔아야 한다"**

- "+7분"은 비용을 말한다 → "11:47 도착"은 결과를 말한다 ✅
- "결과 없음"은 막다른 길이 아니라 분기점이다 — 더 넓게 찾을지 방향을 바꿀지 선택권을 줘야 한다 ✅

**핵심 교훈:**
> 사용자에게 필요한 정보는 "이 선택을 해도 될까?"라는 질문에 답하는 정보다.
> ETA는 "7분 더 걸려도 약속 시간에 맞출 수 있어"를 확인시켜 주고,
> 반경 확장은 "좀 멀어도 되니까 더 찾아줘"라는 사용자의 암묵적 의도에 답한다.
