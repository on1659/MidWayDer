## 1단계: 사용자 여정 기반 UX/UI 리뷰

### A. 사용자 여정 분석 🗺️

#### 시나리오 1: 검색 결과를 받아보는 순간
```
1. 검색 완료 → 10개 결과 카드 리스트 표시
2. 사용자 시선: 1등 카드 → "+0.3km" "+2분" 뱃지 확인
3. "이게 가장 가기 편한 건가?" → 판단 불확실 ❌
4. 2~3번 카드와 비교 → 선택 기준 혼란 ❌
```

**문제점:**
- 뱃지는 많은데 **"왜 이게 좋은 선택인지"** 한 줄 설명이 없음
- 영업 중인 곳과 영업 종료된 곳이 섞여서 표시됨
- "5분 이내 들를 수 있는 곳"과 "15분이 더 걸리는 곳"이 구분 없이 나열

**개선 방향:**
- 카드마다 **스마트 한 줄 요약** → "딱 1분만 더 가면 돼요!", "지금 영업 중! 바로 들르세요"
- **빠른 필터 칩** → "지금 열려있는 곳만", "+5분/10분/15분 이내"

---

#### 시나리오 2: 바쁜 퇴근길 사용자
```
1. 퇴근 시간 → RoutineBanner 뜸 ✅
2. 탭해서 경로 입력 → 검색 ✅
3. 결과 10개 → "어딜 가야 하지?" → 영업 종료된 곳을 클릭 ❌
4. 클릭 후 PlaceDetail 열어서 확인 → 다시 뒤로가기 → 짜증 ❌
```

**문제점:**
- 결과 목록에서 영업 상태가 뱃지로 표시되긴 하지만 **필터가 없어서** 닫힌 곳도 같은 위치에 섞임
- 5분 이내인 곳과 15분이 더 걸리는 곳 구분 없이 나열

---

#### 시나리오 3: 앱을 처음 쓰는 사용자
```
1. 검색 결과 보기 → 카드 정보 스캔
2. "+0.3km +2분" → 이게 좋은 건지 나쁜 건지 모름 ❌
3. "최소 이탈", "빠른 접근" 뱃지 → 의미 이해는 되지만 직관적이지 않음
4. 결국 1등 선택 → UX는 OK지만 설득력 부족
```

**개선 방향:**
- "1분도 안 걸려요 — 바로 들를 수 있어요!" 같은 **자연어 설명** 추가
- 첫 번째 카드에 "이 경로 최고의 선택!" 같은 **확신 언어** 사용

## 4단계: 실제 구현 (상위 2개)

### ✅ 구현 1: 빠른 필터 칩 (ResultList.tsx)

**새로 추가된 기능:**
- `openNowOnly` 토글: 현재 영업 중인 곳만 표시 (business hours 기반)
- `maxDetourMin` 선택: +5분 / +10분 / +15분 이내만 표시
- 필터 적용 시 "N개 표시 중" 안내
- 필터 결과 0개 시 "조건에 맞는 경유지가 없어요 + 필터 초기화" 안내

**구현 방식:**
- `useMemo`로 `filteredResults` 계산 (클라이언트 사이드, 추가 API 호출 없음)
- 기존 `getBusinessStatus()` 함수 재활용
- 필터 상태는 검색 간 초기화되지 않음 (같은 세션에서 연속 검색 시 필터 유지)

**파일:** `src/components/search/ResultList.tsx`

```tsx
// 빠른 필터 상태
const [openNowOnly, setOpenNowOnly] = useState(false);
const [maxDetourMin, setMaxDetourMin] = useState<5 | 10 | 15 | null>(null);

// 필터 적용
const filteredResults = useMemo(() => {
  let res = results;
  if (openNowOnly) {
    res = res.filter((r) => {
      if (!r.place.businessHours) return false;
      return getBusinessStatus(r.place.businessHours).isOpen;
    });
  }
  if (maxDetourMin !== null) {
    res = res.filter((r) => r.detourCost.duration <= maxDetourMin * 60);
  }
  return res;
}, [results, openNowOnly, maxDetourMin]);
```

export async function GET(req: NextRequest) {
  const placeId = req.nextUrl.searchParams.get('placeId');
  const oneHourAgo = new Date(Date.now() - 60 * 60 * 1000);

  const recentClicks = await prisma.clickLog.count({
    where: { placeId, clickedAt: { gte: oneHourAgo } },
  });

  return NextResponse.json({ recentClicks, period: '1시간' });
}
