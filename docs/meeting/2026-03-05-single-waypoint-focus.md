## 2. 핵심 원칙

### 2.1 UX 원칙

> "출발지→도착지 가는 길에 **하나만** 들르는 게 일반적"

**현실적 시나리오:**
```
✅ 일반적: 서울역 → (홍대입구역) → 강남역
❌ 비일반적: 서울역 → (홍대 + 이태원 + 강남CGV) → 강남역
```

### 2.2 기술 vs UX 분리

**기술적 구현:**
- ✅ 여러 개 선택 **기능 유지** (삭제 X)
- ✅ `/api/optimize-route` API 유지
- ✅ MultiStopSelector 컴포넌트 유지

**UX 가이드:**
- ✅ UI상으로 **하나만 선택**하게 유도
- ✅ 추가 선택은 **고급 기능**으로 분리
- ✅ 명확한 안내 메시지

## 3. 새로운 기능

### 3.1 검색창 통합

**기존:** 카테고리만 검색 가능
**변경:** 자유 텍스트 검색 지원

**검색창:**
```
[🔍 어디를 들를까? 검색...]

[추천] [다이소] [스타벅스] [주유소] [올리브영]
```

**사용자 입력 예시:**
1. "다이소" → 카테고리 검색 (기존)
2. "홍대입구역" → 장소 검색 (신규)
3. "이태원 맛집" → 키워드 검색 (신규)

**시나리오 A: 하나만 선택 (기본)**

**시나리오 B: 여러 개 선택 (고급)**

```
4. 이태원 맛집 선택 ✓

6. "경로 최적화하기" 클릭
7. 최적화된 경로 표시
```

## 5. 기술 스펙

### 5.1 API 변경

**검색 API 확장:**
```typescript
POST /api/search
{
  "query": "홍대입구역", // 카테고리 or 자유 텍스트
  "searchType": "category" | "keyword" // 선택사항 (자동 감지)
}
```

**검색 로직:**
```typescript
// 자동 감지
if (query in PREDEFINED_CATEGORIES) {
  // 카테고리 검색 (기존)
  return searchByCategory(query);
} else {
  // 자유 검색 (신규)
  return searchByKeyword(query);
}
```

### 5.2 컴포넌트 수정

**MultiStopSelector.tsx 변경점:**

**Before (현재):**
```tsx
// 여러 개 선택 자유로움
<Checkbox onChange={() => handleToggle(id)} />
{selected.size >= 2 && <Button>최적화</Button>}
```

**After (변경):**
```tsx
// 단일 선택 가이드
<Checkbox
  onChange={() => handleToggle(id)}
  disabled={selected.size >= 1 && !selected.has(id)} // 첫 번째 선택 후 비활성화
/>

{selected.size === 1 && (
  <>
    <Button variant="primary">완료</Button>
    <Button variant="ghost" onClick={enableMultiSelect}>
      다른 경유지 추가하기
    </Button>
  </>
)}

{selected.size >= 2 && (
  <>
    <Alert>⚠️ 여러 경유지 선택 시 더 복잡한 경로가 됩니다</Alert>
    <Button>경로 최적화하기</Button>
  </>
)}
```
