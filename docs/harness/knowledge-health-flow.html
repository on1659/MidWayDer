MidWayDer Knowledge Layer

실수와 교훈이 하네스 개선으로 이어지는 방식

Knowledge base는 진행 기록이 아니라 재발 방지용 기억이다. 5프롬프트마다 health-check 훅이 지금 작업에서 남길 교훈이 있는지, 하네스와 Symphony/Hermes-style 흐름이 제대로 쓰이는지 상기시킨다.

저장소 docs/knowledge/
훅 UserPromptSubmit
주기 5 prompts
상태 파일 .symphony/logs/
Runtime Flow

돌아가는 흐름

1 사용자 프롬프트

Codex 또는 Claude에 새 요청이 들어온다.

2 Hook 실행

UserPromptSubmit이 harness-health-check.sh를 호출한다.

3 카운터 증가

.symphony/logs/harness-health-counter에 횟수를 저장한다.

4 5회마다 점검

5의 배수면 Harness, Symphony, Memory 질문을 띄운다.

5 Knowledge 기록

반복될 만한 실수는 mistakes-and-lessons.md에 남긴다.

What Gets Stored

Knowledge에 저장되는 것

반복 실수

API validation 누락, locale 누락, mobile safe-area 누락, detour score 의미 흔들림.

회귀와 감지 방법

어떤 테스트나 리뷰에서 잡혔는지, 다음에는 어떻게 더 빨리 잡을지.

하네스 문제

route 오분류, Scout 생략, QA 증거 부족, hook 오탐/과차단.

Symphony 운영 교훈

이슈가 너무 컸는지, child issue가 필요했는지, Human Review handoff가 충분했는지.

Hermes-style skill 후보

반복되는 QA/CI/Detour/Naver Maps 절차를 나중에 스킬로 승격할 후보.

What Does Not Belong

저장하지 않는 것

사람 탓

누가 실수했는지는 기록하지 않는다. 원인과 방지책만 남긴다.

비밀값

API key, token, board id, 개인 memory, tracker export는 저장하지 않는다.

검증 안 된 정책 변경

한 번 겪은 일을 곧바로 block hook이나 강제 규칙으로 승격하지 않는다.

일일 작업 로그 전체

진행 기록은 docs/progress/, knowledge는 재발 방지 교훈만.

Files

5프롬프트마다 볼 체크리스트. Harness, Symphony, Hermes-style memory 질문을 정리.

.symphony/logs/harness-health-counter

프롬프트 횟수 카운터. runtime state라 git에 커밋하지 않음.
